# Publishing

## US-030 — YouTube Channel Management
**Persona:** admin. **User story:** As an admin, I want to manage tenant publishing destinations so that producers can publish only to authorized channels. **Entry conditions:** channel-management permission. **Primary journey:** 1. List tenant-owned channels. 2. View safe identity, authorization/connection, locales and defaults. 3. Add/update/disconnect permitted channel settings. **Alternate journeys:** channel is unavailable/degraded. **Failure / recovery journeys:** authorization expiry blocks publish and directs reconnection. **API/domain expectations:** tenant channel resource with server-side credential reference only. **Frontend expectations:** safe identity/status, never OAuth secret. **Security / tenant-isolation requirements:** owner/admin only; channel never crosses tenant. **Idempotency / concurrency requirements:** connect/disconnect uses state preconditions. **Audit requirements:** connection/default changes. **Acceptance criteria:** Given a channel owned by tenant A, when tenant B opens settings, then it is absent. **Open questions:** multiple-brand-account selection. **Existing implementation evidence:** channel lease/publication intent infrastructure exists; channel-management API/UI absent. **MISSING.**

## US-031 — Publish Preparation
**Persona:** producer. **User story:** As a producer, I want to prepare a publication package so that metadata and delivery choices are reviewable. **Entry conditions:** publishable revision and destination access. **Primary journey:** 1. Select approved revision/channel. 2. Prepare title, description, tags, thumbnail, language, captions, visibility and schedule. 3. Validate/persist immutable intent. **Alternate journeys:** save draft without mutation. **Failure / recovery journeys:** invalid channel/metadata returns field-level error. **API/domain expectations:** revision/hash-bound publication intent separate from execution. **Frontend expectations:** source/provenance and stale warning. **Security / tenant-isolation requirements:** no authorization credential exposure. **Idempotency / concurrency requirements:** revision/ETag and intent key. **Audit requirements:** intent create/change. **Acceptance criteria:** Given approved render, when an intent is saved, then its artifact bindings are immutable. **Open questions:** tag/localization defaults precedence. **Existing implementation evidence:** `PublicationIntentBinding` in `packages/persistence/src/postgres-workflow-repository.ts`; API/UI mutation not exposed. **PARTIAL.**

## US-032 — Pre-Publish Validation
**Persona:** producer. **User story:** As a producer, I want a pre-publish gate so that only exact, approved deliverables upload. **Entry conditions:** prepared intent. **Primary journey:** 1. Run gate. 2. Check approved render/audio/duration/captions/thumbnail/metadata/current review/hash consistency. 3. Resolve blockers or authorize execution. **Alternate journeys:** requirements vary by profile/channel/locale. **Failure / recovery journeys:** unknown external state enters reconciliation, never blind retry. **API/domain expectations:** typed gate evidence tied to intent/revision. **Frontend expectations:** requirements and links to correction. **Security / tenant-isolation requirements:** validation result excludes credential internals. **Idempotency / concurrency requirements:** gate snapshot pinned at execution. **Audit requirements:** validation outcome and policy version. **Acceptance criteria:** Given changed thumbnail after approval, when validation runs, then upload is blocked until current approval/intent is established. **Open questions:** channel-specific caption requirements. **Existing implementation evidence:** upload adapter checks dry-run/approval and immutable bindings; no product preflight UI/API. **PARTIAL.**

## US-033 — Publish Episode
**Persona:** producer. **User story:** As a producer, I want to publish an approved revision so that it reaches an authorized YouTube channel. **Entry conditions:** current pre-publish gate, valid channel authorization, allowed visibility. **Primary journey:** 1. Confirm exact intent. 2. Start protected publication effect. 3. Monitor state. 4. Receive video identity/outcome. **Alternate journeys:** private-first policy requires later visibility change. **Failure / recovery journeys:** ambiguous/transient state invokes US-035. **API/domain expectations:** irreversible effect fenced by intent/channel lease, approval and permission recheck. **Frontend expectations:** explicit impact/identity confirmation and no false completion. **Security / tenant-isolation requirements:** server-side OAuth and publication permission. **Idempotency / concurrency requirements:** publication identity/effect record protects duplicate upload. **Audit requirements:** actor, intent, channel, result. **Acceptance criteria:** Given an execution retry after timeout, when prior effect succeeded, then no duplicate video is uploaded. **Open questions:** live-publication authority activation. **Existing implementation evidence:** adapter supports resumable upload; durable API worker/UI intentionally reject irreversible publication (`apps/api/src/job-process.ts`, web disabled). **PARTIAL.**

## US-034 — Scheduled Publishing
**Persona:** producer. **User story:** As a producer, I want future publication scheduling so that releases occur at intended local time. **Entry conditions:** valid intent/channel. **Primary journey:** 1. Choose IANA timezone and local datetime. 2. Show stored instant/timezone. 3. Confirm schedule. 4. Edit/cancel before execution. **Alternate journeys:** DST ambiguity requires user selection. **Failure / recovery journeys:** stale revision cancels execution and requests new intent. **API/domain expectations:** timezone+instant, intent revision and scheduler state. **Frontend expectations:** explicit DST/local-time explanation. **Security / tenant-isolation requirements:** same publication authorization. **Idempotency / concurrency requirements:** update/cancel ETag/fence. **Audit requirements:** schedule/edit/cancel. **Acceptance criteria:** Given DST overlap, when schedule is saved, then selected offset and UTC instant are recorded. **Open questions:** permissible schedule horizon. **Existing implementation evidence:** workflow input includes scheduled mode but current API schema fixes `publicationMode: none`; storage intent has schedule field. **PARTIAL.**

## US-035 — Publishing Failure Recovery
**Persona:** producer. **User story:** As a producer, I want publication-only recovery so that upload faults do not trigger media regeneration. **Entry conditions:** failed/ambiguous publication intent. **Primary journey:** 1. Inspect sanitized upload/reconciliation state. 2. Reconcile by immutable marker. 3. Retry publication effect only when safe. 4. Record final result. **Alternate journeys:** operator escalates unreconcilable state. **Failure / recovery journeys:** non-idempotent ambiguity stays blocked. **API/domain expectations:** recovery identity/marker, effect state and retry classification. **Frontend expectations:** clear “do not regenerate” boundary. **Security / tenant-isolation requirements:** no provider receipt/secrets. **Idempotency / concurrency requirements:** fenced effect and reconciliation precondition. **Audit requirements:** attempts/reconciliation. **Acceptance criteria:** Given upload timeout, when reconciliation finds the marker, then intent becomes published without a second upload. **Open questions:** recovery SLO/ownership. **Existing implementation evidence:** `packages/youtube-upload/src/publication-reconciliation.ts` and tenant scheduler; mutation UI absent. **PARTIAL.**

## US-036 — Post-Publish State
**Persona:** producer. **User story:** As a producer, I want durable publication state so that I can identify what was released. **Entry conditions:** publication intent exists. **Primary journey:** 1. Open publication. 2. View status, YouTube ID, timestamp, source revision/locale/channel/metadata state. 3. Navigate to evidence. **Alternate journeys:** `reconciliation_required` is visibly non-terminal. **Failure / recovery journeys:** missing external confirmation directs US-035. **API/domain expectations:** safe read model binds immutable revision/approval/artifact hashes. **Frontend expectations:** distinguish ready, publishing, published and reconciliating. **Security / tenant-isolation requirements:** public/private destination metadata policy. **Idempotency / concurrency requirements:** immutable success bindings. **Audit requirements:** execution/result. **Acceptance criteria:** Given completed publication, when read, then video ID and source revision/hash are returned without credentials. **Open questions:** post-publish metrics scope. **Existing implementation evidence:** safe `getPublication` API and reconciliation persistence; web display disabled. **PARTIAL.**

## US-037 — Metadata-Only Update
**Persona:** producer. **User story:** As a producer, I want to update supported publishing metadata without rerendering so that editorial corrections are low-impact. **Entry conditions:** published/authorized destination and mutable fields. **Primary journey:** 1. Edit allowed metadata. 2. See render-affecting fields excluded. 3. Validate/channel update. 4. Record outcome. **Alternate journeys:** metadata change requires re-review when policy says. **Failure / recovery journeys:** provider failure retries metadata effect only. **API/domain expectations:** separate metadata revision/effect bound to video identity. **Frontend expectations:** clearly states no regeneration/render and exceptions. **Security / tenant-isolation requirements:** server OAuth only. **Idempotency / concurrency requirements:** effect key and current remote version where available. **Audit requirements:** before/after. **Acceptance criteria:** Given only description change, when saved, then render hash remains unchanged. **Open questions:** which YouTube fields and audit retention. **Existing implementation evidence:** YouTube metadata generation/update primitives exist in `packages/metadata`/upload adapter; SaaS mutation journey absent. **PARTIAL.**
