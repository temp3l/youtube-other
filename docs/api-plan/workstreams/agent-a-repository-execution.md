# Agent A — Repository and execution-path findings

## Scope and evidence convention

- **Verified** — This workstream is based on source inspection only. The root `README.md`, `docs.bak`, generated output trees, and compiled `dist/` trees were not used as architecture evidence. The controlling instructions were `AGENTS.md` and `AGENTS.api-planning.md`.
- **Verified** — Commands used for inspection were targeted `find`, `rg`, `sed`, and a read-only Node script over workspace `package.json` files. No tests or provider calls were run, because this workstream changed documentation only.
- **Unresolved** — Runtime behavior against real episode fixtures, paid providers, remote render workers, and YouTube was not executed. Findings about crash windows and cross-process behavior are therefore code-path analyses, not production incident reproductions.

## Repository and entry-point inventory

- **Verified** — The repository is a `pnpm` workspace containing `apps/*` and `packages/*` (`pnpm-workspace.yaml`). The root scripts route the operational commands through `apps/cli/bin/mediaforge.js`, usually through `scripts/run-with-telemetry.mjs` (`package.json` scripts `mediaforge`, `episode:*`, `render`, `youtube:upload`, and others).
- **Verified** — `apps/cli` is the only broad application entry point. Its package directly depends on nearly every domain and infrastructure package, including `@mediaforge/story-localization`, `@mediaforge/speech`, `@mediaforge/image-generation`, `@mediaforge/rendering`, `@mediaforge/youtube-upload`, `@mediaforge/math-education`, `@mediaforge/workflow-engine`, and `@mediaforge/persistence` (`apps/cli/package.json`). Command registration and many implementations coexist in the 4,000-plus-line `apps/cli/src/index.ts`, supplemented by focused command files.
- **Verified** — The CLI launcher is itself a subprocess adapter: `apps/cli/bin/mediaforge.js` spawns Node against `apps/cli/dist/index.js` and forwards arguments and inherited environment. Story-level audio and image wrappers spawn this launcher again through `@mediaforge/process-runner` (`apps/cli/src/story-audio-command.ts:runAudioTarget`; `apps/cli/src/story-images-command.ts:runImagesEpisode`).
- **Verified** — The existing HTTP application is not a production API. `startApiServer()` creates a bare Node HTTP server that ignores the request and returns `{ok: true, workspace: config.workspaceDir}` for every request; it has no routes, authentication, authorization, request validation, workflow dispatch, or error contract (`apps/api/src/index.ts:startApiServer`). Its package depends only on config, domain, persistence, and shared packages (`apps/api/package.json`).
- **Verified** — The web application is a static HTML string, not an operational surface (`apps/web/src/index.ts:renderHomePage`).
- **Verified** — A separate executable, `packages/educational-renderer/bin/educational-renderer.js`, exposes `validate`, `render`, `render-scene`, `compose`, `inspect`, `benchmark`, and cache commands over `createEducationalRenderer()` (`packages/educational-renderer/src/cli.ts`). This is a genuine second process entry point for math rendering.
- **Verified** — `scripts/generate-youtube-metadata.sh` and `scripts/openai-generate-scene-image.sh` are thin adapters back to the main CLI. `scripts/remote-render-worker.mjs` is a direct remote-render worker entry point. `scripts/youtube-auth.ts` is a standalone interactive Google OAuth credential acquisition entry point. These scripts do not provide a shared application layer.
- **Verified** — `packages/source-ingestion` exposes local-file, YouTube, and TikTok source adapters, but YouTube and TikTok transcript acquisition deliberately raise `HumanActionRequiredError`; the main horror production paths instead discover repository markdown sources (`packages/source-ingestion/src/index.ts`; `packages/dark-truth/src/index.ts:discoverEpisodeSources`).

## Current execution models

- **Verified** — Imperative Dark Truth production is implemented mostly as CLI functions that read and write episode directories and invoke low-level packages directly. Examples are `commandEpisodeEnglish()` → `runEpisodeFullSetupUseCase()` → `prepareEpisodeLanguage()` (`apps/cli/src/episode-commands.ts`), `commandStoriesRender()` → `FFmpegVideoRenderer.render()` (`apps/cli/src/story-render-command.ts`), and `commandYoutubeUpload()` → `uploadYoutubeEpisode()` (`apps/cli/src/index.ts`, `packages/youtube-upload/src/index.ts`).
- **Verified** — A story-specific workflow model exists, with planned stages, outcomes, retryability, artifacts, and a file-backed `StoryWorkflowManifestStore` under `<episode>/state/story-workflow/workflows/<workflowId>.json` (`packages/story-localization/src/story-workflow-planner.ts`, `story-workflow-store.ts`, `story-workflow-status.ts`). However, `stories pipeline` rejects non-dry-run execution, and `stories production resume` only prints an actionable plan; these surfaces do not execute the stage graph (`apps/cli/src/story-pipeline-command.ts:commandStoriesPipeline`; `apps/cli/src/story-production-command.ts:commandStoriesProductionResume`).
- **Verified** — The generic workflow engine is executable and materially stronger: `WorkflowOperator` provides initialize, status, `runNext`, `runTask`, resume, retry, invalidation, reconciliation, cache inspection, locks, attempts, and immutable JSONL events (`packages/workflow-engine/src/workflow-operator.ts`; `workflow-store.ts`). State lives under `<unit>/state/workflow/<workflow-id>/` with `events.jsonl`, projected `state.json`, attempts, approvals, overrides, locks, and cache decisions.
- **Verified** — Canonical math private production actually binds all executable math tasks through `createCanonicalMathOperator()` and `createMathProductionTaskImplementations()` (`apps/cli/src/math-workflow-runtime.ts:createCanonicalMathOperator`; `packages/math-education/src/orchestration/canonical-task-adapters.ts:MATH_EXECUTABLE_TASK_IDS`). It is the closest current code to the desired shared application/workflow layer.
- **Verified** — Dark Truth has a complete typed task definition graph, but `workflow episode` constructs `createDarkTruthTaskRegistrations({}, readiness)` with an empty implementation map. The operator can plan and report readiness, but production tasks are unbound and cannot replace the imperative horror CLI (`apps/cli/src/workflow-commands.ts:createOperator`; `packages/dark-truth/src/task-registry.ts:createDarkTruthTaskRegistrations`).
- **Inferred** — The feasible migration anchor is the generic workflow engine plus extracted application-use-case factories, because math already proves that CLI code can construct one canonical operator while retaining domain-specific task graphs.
- **Recommended** — Do not make HTTP controllers call the current Dark Truth command functions or spawn `mediaforge`. First bind Dark Truth task definitions to existing package services behind typed use cases, then have CLI, API, worker, and scheduler adapters call those use cases.

## Required operation traces

Each trace records entry point, service path, direct infrastructure, state/files, gates, retry/idempotency, logs/audit, external effects, and API-reuse safety.

### 1. Create or load an episode / lesson

- **Verified** — Dark Truth has no single create/load application use case. `stories rewrite-full` resolves a source and materializes `<episode>/source/<canonical-name>.md` (`apps/cli/src/story-full-rewrite-command.ts`; `packages/story-localization/src/short-rewrite.bootstrap.ts:materializeCanonicalSourceStory`). `images resume` can independently bootstrap `<episode>/manifest.json` from a source and scene plan (`apps/cli/src/images-resume-command.ts:loadOrBootstrapEpisodeManifest`). General CLI readers scan every workspace directory for `manifest.json` and may mutate it to attach legacy scene-plan or rewritten-script data (`apps/cli/src/index.ts:readManifestForEpisode`).
- **Verified** — The SQLite persistence package supports `episodes(episode_id, manifest_json, created_at, updated_at)`, but production CLI references only call `migrate()`; no production caller invokes `saveEpisodeManifest()` or `loadEpisodeManifest()` (`packages/persistence/src/index.ts:SQLitePersistence`; `apps/cli/src/index.ts:loadCliRuntime`, `commandDbMigrate`). Files are therefore the effective authority.
- **Verified** — Math creates a deterministic lesson ID and unit root as part of either the legacy pilot simulator or canonical operator construction (`packages/math-education/src/domain/identity.ts:createLessonId`; `packages/math-education/src/orchestration/pilot-simulation.ts:runPilotSimulationUnlocked`; `apps/cli/src/math-workflow-runtime.ts:createCanonicalMathOperator`). The legacy path writes `<lesson>/manifest.json`; the canonical operator writes generic workflow state below the unit.
- **Verified** — Validation is Zod-based for episode and workflow manifests. Writes are atomic in shared helpers, but workspace scanning and bootstrap are not guarded by a unit-level lock. The generic math operator derives a deterministic workflow instance ID and uses workflow locks.
- **Verified** — Creation has no tenant, actor, audit event, or request id. It produces local filesystem side effects only. Telemetry starts at the CLI process, not at a create-use-case boundary (`apps/cli/src/index.ts` execution telemetry setup).
- **Recommended** — API reuse is unsafe until `CreateContentUnit` and `GetContentUnit` use cases define one authority and transaction boundary. Treat current filesystem episode discovery as a migration adapter, not a public resource lookup.

This is a divergent full-production path, not merely a thin story-generation adapter.
- **Verified** — `stories pipeline` can build the desired stage graph but is dry-run-only (`apps/cli/src/story-pipeline-command.ts:commandStoriesPipeline`).
- **Verified** — Math has two generation paths. `math lesson generate --simulate` calls the legacy `runPilotSimulation()` state machine (`apps/cli/src/math-commands.ts:simulate`; `packages/math-education/src/orchestration/pilot-simulation.ts`). `math production run|resume` calls a canonical `WorkflowOperator` whose executable tasks cover curriculum through publish dry-run (`apps/cli/src/math-commands.ts:runCanonicalPrivateProduction`; `packages/math-education/src/orchestration/canonical-task-adapters.ts`).

Canonical math has task fingerprints, artifact verification, attempt records, retry/resume, and locks.
- **Verified** — External effects are OpenAI-compatible generation and filesystem writes. Operational logs use Pino and provider debug/telemetry files; no immutable actor audit event is recorded for generation.
- **Recommended** — `localizeStoryEpisode()` and canonical math task implementations are reusable service assets, but neither CLI action is the API boundary. Wrap each in domain-specific typed use cases submitted through the canonical workflow engine.

### 12. Publish to YouTube

- **Verified** — The active Dark Truth entry point is `youtube upload`, which resolves local manifest, channel credentials by language, metadata, video and thumbnail paths, then calls `uploadYoutubeEpisode()` (`apps/cli/src/index.ts:commandYoutubeUpload`).
- **Verified** — `uploadYoutubeEpisode()` hashes inputs, writes a `planned` report, calls YouTube `videos.insert`, optional `thumbnails.set`, optional `playlistItems.insert`, and verification, then overwrites the report as `uploaded` or `failed` (`packages/youtube-upload/src/index.ts:uploadYoutubeEpisode`; `youtube-mutation-seam.ts:executeYoutubeMutationSequence`).
- **Verified** — A prior uploaded report skips a repeat only when video, thumbnail, metadata hash/title match and `--force` is absent. There is no durable unique publication record, provider-side idempotency key, or recovery query keyed by local request fingerprint.
- **Inferred** — A crash after `videos.insert` succeeds but before the final local report is written can leave only the `planned` report; retrying will call `videos.insert` again and can duplicate the video. The success callback records request IDs only in memory until the final report.
- **Verified** — A stronger generic `publishYoutubeMedia()` exists with publish approval validation, request fingerprints, prior-report authority checks, per-operation checkpoints, and resume of thumbnail/playlists when a prior `videoId` exists (`packages/youtube-upload/src/generic-media-publish.ts`). No production source caller uses it; usages are tests only.
- **Verified** — Math live publishing is disabled. `math publish` requires `--dry-run`, and canonical production stops at publish dry-run (`apps/cli/src/math-commands.ts`).
- **Recommended** — The active uploader is not API-safe. Wire a single publication use case around the generic publisher plus durable transactional checkpoints/outbox and provider reconciliation before enabling HTTP publishing.

### 14. Execute a batch

- **Verified** — There are at least four batch implementations: story OpenAI Batch lifecycle (`stories batch`/`stories:batches`), image OpenAI Batch lifecycle (`images batch`), generic `BatchCoordinator` (`batch plan|run|resume|status|reconcile|cancel`), and math private batch scheduling (`math batch`) (`apps/cli/src/story-localization-commands.ts`; `images-batch-commands.ts`; `workflow-commands.ts`; `math-commands.ts`).

### 15. Resume an interrupted workflow

- **Verified** — Story resumption is fragmented: rewrite commands have `--resume` cache behavior; `stories pipeline --resume <workflowId>` only loads a manifest during dry-run planning; `stories production resume` only prints a plan; `images resume` executes eligible scenes; provider batches have independent resume/import/retry commands (`apps/cli/src/story-full-rewrite-command.ts`; `story-pipeline-command.ts`; `story-production-command.ts`; `images-resume-command.ts`).
- **Verified** — The story workflow store can append attempts/outcomes atomically under a file lock, but no inspected operator executes every planned story stage from that store (`packages/story-localization/src/story-workflow-store.ts`).
- **Verified** — Legacy math simulation resumes by validating sequential stage fingerprints/artifacts in `<lesson>/manifest.json` and recomputing from the first invalid stage (`packages/math-education/src/orchestration/pilot-simulation.ts`).
- **Verified** — Canonical math reconciles stale locks/attempts, transitions `interrupted` to pending for `resume()`, transitions `failed` to pending for `retryFailed()`, verifies artifacts, and reruns the same task implementation (`packages/workflow-engine/src/workflow-store.ts:recoverStaleRecords`; `workflow-operator.ts:resume`, `retryFailed`, `reconcile`).

- **Recommended** — Canonical workflow-engine semantics are API-reusable. Dark Truth must migrate to them before claiming workflow-level resume; until then, expose no stronger guarantee than the underlying task actually provides.

## API reuse readiness by subsystem

- **Verified** — Canonical math operator/task implementations: **high internal reuse readiness**, subject to moving the operator factory out of `apps/cli` and adding durable shared persistence/queue execution.
- **Verified** — Generic workflow engine and batch coordinator: **medium-high semantic reuse readiness**, but filesystem stores and process/PID locks are not sufficient for horizontally scaled API workers.
- **Verified** — Story localization, staged speech, image generation, renderers, metadata, and generic publisher packages: **medium service reuse readiness**; they have typed contracts and tests, but need application commands, tenant-aware ports, and unified state.
- **Verified** — Dark Truth imperative CLI/episode orchestration: **low direct API reuse readiness** because it mixes parsing, config, stdout/exit codes, filesystem discovery, subprocesses, provider calls, and multi-stage mutations.
- **Verified** — Existing `apps/api`: **not reusable as a production contract** beyond its process bootstrap.
- **Recommended** — Extract use cases in this order: content-unit registration/load; workflow start/status; story generation/localization; narration; images; render; validation/approval; publication. Migrate CLI commands to those use cases before enabling equivalent HTTP mutations.

- **Verified** — Building a shared application/workflow layer is feasible because the generic workflow engine and canonical math implementation already demonstrate task bindings, fingerprints, artifact verification, retries, resume, and batch reuse.
