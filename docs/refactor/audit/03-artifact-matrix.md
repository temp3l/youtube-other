# Artifact Producer, Consumer, and Path Matrix

## Resolver intent and policy

The proposed key is a strict `ArtifactRef` with these dimensions:
`profileId`, `productionId` (`episodeId` or `lessonId`), `artifactType`, optional
`stage`, `locale`, `variant`, `sceneId`, `renderProfile`, and `schemaVersion`.
Physical paths are returned only by the profile layout adapter. Attempts and
provider IDs belong in lineage/state, not stable output names.

Canonical write policy: containment and symlink checks, validate payload before
write, write a same-filesystem temporary object, fsync where supported, verify
content hash, atomically promote artifact and manifest, then append the state
event. Canonical writes never update a legacy mirror.

Legacy read policy: validate canonical first, then the ordered candidates listed
below. Return provenance for the selected candidate. Multiple valid differing
candidates are a conflict, not “newest wins.” Invalid content is reported; a
read does not quarantine, repair, rename, or delete it.

## Artifact migration acceptance tests

- Path traversal, absolute input, backslash portability, symlink target, symlink
  ancestor, and realpath escape all fail before reads or writes.
- Canonical-only, legacy-only, same-content dual candidate, differing dual
  candidate, invalid canonical, invalid legacy, and absent cases return the
  documented provenance/error.
- Locale and variant are never inferred from a directory name when present in a
  manifest; Portuguese is included where the profile supports it.
- Dry-run performs zero filesystem writes, including locks, temp files, cache,
  quarantine, logs, and migration state.
- Migration copies, validates, hashes, promotes, records rollback, and leaves
  the source intact. Rollback validates both current and recorded hashes.
- Every consumer is searched and migrated before any legacy writer/path helper
  is removed; packaged CLI tests run after rebuilding affected packages.
