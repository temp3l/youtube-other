## Removal protocol

For each `CONSOLIDATE` or `REMOVE` row:

1. Freeze the characterization named in the row before behavior changes.
2. Select and version the canonical task/contract; document any deliberate
   contract change and classify affected fixtures.
3. Add the adapter and migrate every listed caller, including root npm scripts,
   help output, API/web/bin callers, tests, and packaged runtime.
4. Search again for symbol imports, command strings, direct providers, paths,
   schemas, writers, and `dist` dependencies. Explain every remaining hit.
5. Prove dry-run, legacy read, canonical write, state replay, error/exit mapping,
   telemetry/redaction, and rollback.
6. Remove only after focused, compatibility, and packaged-CLI checks pass and
   the operator accepts the compatibility window. Record the final disposition
   and commit in the implementation report.

No row authorizes fixture updates. A failing fixture is changed only after its
contract classification is accepted; assertions are never weakened.
