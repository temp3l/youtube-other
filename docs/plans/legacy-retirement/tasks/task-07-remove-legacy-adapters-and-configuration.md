# Task 07: Remove Legacy Adapters And Configuration

## Objective

Delete compatibility code only after its callers, data, rollback window, and
operator obligations have cleared their gates.

## Scope

Legacy narration mode and monolithic generation, expired path candidates and
projections, direct uploader, obsolete caller adapters, old configuration,
legacy shot/layout migration tools, and import normalization adapters.

## Procedure

1. Review the retirement register and refuse removal for any unmet gate.
2. Remove one compatibility family at a time, including its exports, config,
   environment variables, tests, fixtures, and operational documentation.
3. Retain historical-schema readers only when supported stored artifacts still
   require them; isolate them under explicit import/reconciliation APIs.
4. Remove migration tools only after the approved data population is migrated
   or formally accepted as retained.
5. Convert unexpected stale layouts into actionable errors, not silent fallback.
6. Update generated AI context through its owning generator if source docs
   change; do not hand-edit generated context files.

## Validation

- Each family has focused replacement tests before deletion.
- Targeted searches find no active caller, config key, write path, or undocumented
  fallback for the removed family.
- No fixtures or assertions are weakened solely to permit removal.

## Completion gate

Every deleted adapter has recorded gate evidence and rollback history; remaining
legacy readers are import-only, owned, and time-bounded or intentionally durable.
