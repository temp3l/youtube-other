# This prompt supersedes the previous research-first prompt

Do not implement the previous requirement that every existing History script must undergo a new OpenAI research and provenance pass.

The new product decision is:

> History stories supplied to or generated by the pipeline are trusted by default. The pipeline must treat the canonical narration as editorially verified input and must not automatically perform OpenAI research, web search, source retrieval, or evidence assessment.

Independent research remains available only through an explicit opt-in mode.

# Primary objective

Implement a History authoring and visual-planning workflow with three explicit authority modes:

```ts
type HistorySourceAuthorityMode =
  | "trusted-script"
  | "research-backed"
  | "unverified-external";
```

## Default

For all newly imported or generated History stories:

```text
sourceAuthorityMode: trusted-script
```

Unless explicitly overridden by the user or episode metadata.

## Meaning of each mode

### `trusted-script`

- canonical narration is accepted as factually verified by the story owner;
- no automatic OpenAI research;
- no automatic web search;
- no automatic source retrieval;
- no automatic evidence assessment;
- no requirement for persisted external source references;
- factual visual planning is allowed;
- claims must be structurally extracted and bound to narration;
- provenance status must be honest and distinguish trust from independent evidence.

### `research-backed`

- explicit opt-in;
- uses the existing live research pipeline;
- persisted sources and evidence required;
- deterministic provenance evaluation required;
- suitable for episodes requiring independently auditable sourcing.

### `unverified-external`

- imported script not explicitly trusted;
- factual visual planning remains blocked;
- may be promoted to `trusted-script` through explicit attestation;
- may be moved to `research-backed` through explicit research workflow.

Do not infer trust from the presence of a script alone. Use the configured default plus persisted authority metadata.

# Canonical status model

Extend provenance status additively:

```ts
type ClaimProvenanceStatus =
  | "supported"
  | "partially_supported"
  | "contested"
  | "contradicted"
  | "unresolved"
  | "not_required"
  | "trusted_input";
```

## `trusted_input`

Means:

> This claim is accepted because the canonical narration was explicitly trusted under a valid, hash-bound History trust attestation. It was not independently verified by the pipeline.

Do not map `trusted_input` to `supported`.

Do not create fake:

- source references;
- evidence fragments;
- citations;
- evidence assessments;
- provider runs;
- token usage;
- web-search activity.

Approval and review artifacts must preserve the distinction.

# Workstream 2 — Add explicit trust attestation

Implement an append-only trust attestation equivalent to:

```ts
interface TrustedNarrationAttestationV1 {
  schemaVersion: "history-trusted-narration-attestation.v1";
  episodeId: string;
  narrationHash: string;
  normalizationVersion: string;
  authority: "user" | "content-pack-owner" | "editorial-workflow";
  authorityName: string | null;
  scope: "entire-narration" | "selected-claims";
  selectedClaimIds: string[];
  assertion:
    | "factually-verified"
    | "accepted-without-independent-verification";
  assertedAt: string;
  policyVersion: string;
  parentAttestationId: string | null;
  invalidatedAt: string | null;
  invalidationReason: string | null;
  id: string;
}
```

Application code must generate the attestation ID deterministically or through an established auditable ID strategy.

## Default assertion

For imported/generated History stories under the default trusted-script mode:

```text
authority: editorial-workflow
assertion: accepted-without-independent-verification
scope: entire-narration
```

If the user explicitly marks the story factually verified, allow:

```text
authority: user
assertion: factually-verified
```

Do not claim independent verification in either case.

## Hash binding

The attestation must bind to:

- canonical normalized narration hash;
- normalization version;
- episode ID;
- selected claim IDs when scope is partial;
- policy version.

A mismatched narration hash invalidates the attestation for materially changed claims.

# Workstream 4 — Extract claims without factual research

Trusted stories still need structured claims for:

- maps;
- diagrams;
- timelines;
- labels;
- entity tracking;
- chronology;
- shot bindings;
- aspect-ratio adaptations;
- invalidation.

Implement a claim-structuring pipeline that does not perform research.

## Preferred order

1. consume claim bindings already emitted by the story-generation workflow;
2. reuse persisted claims when narration facts are unchanged;
3. use deterministic extraction for obvious claims;
4. optionally use a non-research semantic structuring provider only when explicitly enabled;
5. otherwise preserve uncertain compound text as a trusted claim group rather than inventing structure.

## Default behavior

Default trusted-script processing must work without OpenAI.

Use deterministic parsing for:

- dates;
- years;
- quantities;
- percentages;
- named entities already represented in metadata;
- explicit locations;
- quotations;
- sentence and clause boundaries;
- chronology markers;
- claim-bearing narration units.

Do not pretend deterministic extraction provides semantic verification.

## Optional semantic structuring

Allow an explicit optional mode:

```text

```

This may use a configured model to split compound claims or improve entity roles, but:

- it must not use web search;
- it must not retrieve sources;
- it must not change authority mode;
- it must not mark claims supported;
- it must remain cacheable and resumable;
- it must be disabled by default.

# Workstream 7 — Approval policy for trusted-script mode

Update the four approval gates:

```text
structural
editorial
content
production
```

## Content approval

A material claim may satisfy the content gate when:

```text
provenanceStatus === trusted_input
AND
trust attestation exists
AND
attestation narration hash matches
AND
attestation is not invalidated
```

Do not require source references or evidence fragments in trusted-script mode.

Content approval remains blocked when:

- attestation is missing;
- narration hash no longer matches;
- material claim is outside a partial attestation scope;
- claim binding is broken;
- a factual visual introduces details not present in trusted narration;
- an unresolved factual delta exists;
- authority mode is `unverified-external`.

## Review wording

Use:

```text
Accepted from trusted script
```

Do not use:

```text
Independently verified
Supported by sources
Research-backed
```

unless the episode actually uses research-backed mode.

# Workstream 8 — Trusted factual visual planning

Allow factual visual planning from trusted claims.

Every factual visual must bind to:

- trusted claim IDs;
- narration span;
- trust attestation ID;
- protected factual meaning;
- uncertainty markers;
- visual modality;
- forbidden unsupported additions.

Generate:

- maps;
- map states;
- diagrams;
- timelines;
- archival-image intents;
- document/quotation cards;
- comparison cards;
- restrained reconstructions;
- beat and shot plans;
- 16:9 plans;
- 9:16 plans.

## Visual fidelity rule

A visual may depict only what is explicitly or reasonably implied by the trusted narration.

Do not add unsupported specificity such as:

- exact troop routes not stated;
- exact territorial borders not stated;
- precise uniforms or equipment not stated;
- exact casualty figures not stated;
- quotations not present;
- causal relationships stronger than narration;
- named people absent from the claim;
- speculative diagram edges.

When the trusted narration is broad, the visual must remain broad.

## Map and diagram validation

Replace evidence-bound validation in trusted-script mode with narration-bound validation:

- every route must be present or clearly implied in narration;
- every actor must appear in the trusted claim;
- every date/period must be in the trusted claim;
- every diagram edge must reflect an expressed relationship;
- labels must not add new factual assertions;
- uncertainty must be preserved.

Research-backed mode retains source/evidence validation.

# Workstream 11 — Incremental trust invalidation

Implement factual-delta handling.

## Changes that do not invalidate trust

- punctuation;
- Markdown;
- whitespace;
- paragraph movement;
- line wrapping;
- equivalent rephrasing;
- sentence splitting/merging without factual change;
- visual changes;
- shot changes;
- timing changes;
- rendering changes;
- aspect-ratio changes;
- thumbnail changes.

These may require span realignment but not re-attestation.

## Changes that invalidate affected trusted claims

- new factual assertion;
- changed date;
- changed number;
- changed person or institution;
- changed location;
- changed quotation;
- changed causal relationship;
- changed route;
- stronger certainty;
- removed uncertainty;
- materially changed interpretation.

Do not invalidate unrelated claims.

## Resolution

For affected claims, allow:

1. explicit user/editorial re-attestation;
2. optional research-backed verification;
3. removal or revision of the changed claim.

No automatic OpenAI research.
